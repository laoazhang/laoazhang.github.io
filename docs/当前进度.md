## 访问统计（GoatCounter）

不蒜子已失效（接口 502），改用 **GoatCounter**（开源、可迁移，免费非商业托管）。

配置步骤：

1. 在 https://www.goatcounter.com/ 注册，拿到站点 code（如 `laoazhang`）
2. 后台 Settings 勾选 **"Allow adding visitor counts on your website"**（默认关闭）
3. 在 `_config.yml` 填 `goatcounter_code: "laoazhang"`
4. 重新构建部署

实现方式：

- `_includes/_head.html` 注入追踪脚本与 `window.GOATCOUNTER_BASE`
- **`count.js` 自托管**在 `assets/js/goatcounter-count.js`（原样 vendored，ISC 许可）。
  不要改回 `//gc.zgo.at/count.js`：国内拉那个 9KB 文件要 **15 秒**，
  `async` 脚本没加载完访客就走了 → hit 直接丢失。自托管后本地 1ms、线上同源。
- `assets/js/counter.js` 请求 `/counter/TOTAL.json` 和当前页 `.json`，
  填入 `.js-site-pv` / `.js-page-pv`
- **查询路径必须按 canonical 走**，和 `count.js` 的 `get_path()` 一致。
  `about.md` 的 permalink 是 `/about/index.html`，但 canonical 是 `/about/`；
  用 `location.pathname` 会查到 `GoatCounter` 从没记录过的路径，永远显示 0。
- 块级显隐：`.js-counter-site` / `.js-counter-page` 各自独立，
  TOTAL 拿不到时不会留下 "Total  views." 这种残缺文案

注意：

- **本地预览永远不计数**。`count.js` 第 116 行主动跳过 `localhost` / `127.` /
  `192.168.` 等地址（除非设 `allow_local`），所以本地看到 0 是正常行为，
  要验证得访问线上。
- **计数天生滞后，这是设计，不是 bug**。依据 `handlers/vcounter.go`：
  - 进程内缓存 `zcache.New(time.Hour*4, time.Hour*8)` —— 4 小时过期，
    8 小时内仍可返回旧值；过期后**先返回旧值**，再起 goroutine 后台刷新
  - 响应头 `Cache-Control: public` + `Expires: now + 4h`，浏览器/CDN 再缓存 4 小时
  - `Age` 头是服务端自己算的（`time.Since(c.created)`），不是 CDN 的
  所以页面上的数字最多可能差几个小时。**TOTAL 和单页 `.json` 完全一样**。
- **不要加 `?cb=时间戳` 绕缓存**。作者把缓存键显式写成
  `siteID + "-" + path + "." + ext + "-" + start + "-" + end`，源码注释原话：

  > Don't need to take options in to account for cache. Some people are using
  > "cache buster" URL params so can't use all of r.URL.

  查询参数压根不参与缓存键，加了只会拿到同一份缓存，**既不刷新数据，
  又让每次浏览多打一次 GoatCounter 的服务器**。想看实时数字去后台看
  （后台直查数据库，不走这个缓存接口）。
- GoatCounter **没有独立访客数**（`count_unique` 已废弃），所以 about 页
  第二行显示的是"本页浏览量"。
- 官方文档明确：页面浏览约 10 秒内出现在后台；看不到先查广告拦截器
  （`goatcounter.com` / `gc.zgo.at` 常在拦截列表里）。
